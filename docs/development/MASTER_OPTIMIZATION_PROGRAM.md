## Implemented on production paths

- Semantic V2 `search`: up to eight cached query vectors (24KiB vector payload), hashed immutable descriptors including model space/task/backend, project/index generation/configuration revision. Every search rechecks READY/current index, document scope and ranking. No source/result cache, no media-path caching, no routing-model change. Concurrent configuration change is rejected before publishing evidence. Controlled repeated queries reduced native compute count 2 to 1; not a phone speed/quality claim.
- Performance screen: comparable cohorts with p50/p95 TTFT and decode speed; device/API/model SHA/runtime/suite/task/mode/configuration/effective backend/TTFT boundary stay separate. Missing/invalid metrics do not become zeros, wrong-answer/cancelled runs do not inflate successful speed, unverified model hashes are split by run. P95 nearest-rank is exploratory with fewer than 20 samples. Observed PSS endpoints are not peak memory or battery energy.
- Local Artifact API, reused native OpenApiTool/ToolRegistry: `artifacts.create`, `read`, `revise`, `list`. Tools Auto includes the new tools for fresh/default profiles; existing stored selections remain unchanged until the user chooses Auto/enables them. Tools Off still means no model tools, not no logical Agent. Custom Agent/Skill restrictions remain; General and built-ins offer app capabilities.
- Private artifacts use independent filesystem storage, no Room migration. Immutable revisions, original snapshots, file and descriptor SHA-256, expected-version conflict rejection, private same-filesystem commit after validation/fsync, cross-process file locking. Incomplete pending directories are not exposed as complete revisions; prior committed versions remain recoverable. Power-loss/storage-exhaustion behavior on the target phone is not validated.
- Chat menu Artifacts: verified text/structure preview, raw descriptor editor, before/after text, inspection/restoration of older versions as new revisions, explicit SAF export/readback hash and explicit open-with-reader action. Not WYSIWYG; not a pixel/PDF/slide renderer. Pending export identity survives activity recreation; unsaved editor changes are not a persisted job.
- XLSX: multiple sheets, bounded exact A1 cells, values/types, formulas and supplied caches, header style. No evaluation; formulas are a documented restricted function subset, no external/active formulas. Cache values may remain stale after editing dependencies; external Excel may recalculate on open. Structured Excel Tables/date-format editing/imported-workbook mutation are not implemented.
- DOCX: paragraph styles, headings, lists, page breaks and real rectangular tables with column grid. No imported-original rewriting, images, headers/footers or perfect Word layout preservation.
- PDF: actual multipage text documents and textual table rows using existing PDFBox. Controlled regeneration from the descriptor; no arbitrary existing-PDF editing or annotations. Standard fonts support the tested Spanish text; unsupported glyphs fail rather than disappear.
- PPTX: real text slides, bounded boxes, relationships to blank layout/master/theme; independently reopened with python-pptx including layout/master. Images/charts/animations and viewer fidelity on Android remain pending.
- CODE: actual UTF-8 individual files including Unicode names and empty files; exact original/new content stored in versions. No execution, syntax guarantee, repository/project editing or general unified-patch application.
- Documents: strict bounded DOCX body text-node extraction retains word runs and table/paragraph separators; PPTX imports in presentation relationship order with actual slide numbers. Headers/footers/notes/style-position metadata are not claimed. `files.read` supports exact sheet/range up to 64 cells, missing addresses/abstention, no homonymous-sheet substitution, no oversized JSON truncation. Source/project scope is retained.
